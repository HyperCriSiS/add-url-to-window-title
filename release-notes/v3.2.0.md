# Add URL To Window Title v3.2.0

First stable release of the modernized fork.

## Highlights

- Robust title lifecycle handling for titles that are created late, replaced, moved, or repeatedly overwritten.
- SPA URL tracking through the Navigation API and History API fallback without a permanent one-second polling timer.
- Title rebasing and mutation backoff to prevent duplicated URL suffixes and reduce title-fight overhead.
- Delegated input-focus handling instead of per-input listeners and whole-page input MutationObservers.
- Three URL display modes: hostname, full URL, and full URL without query/fragment.
- Normal punctuation such as apostrophes is preserved.
- New page diagnostics popup that identifies restricted/unsupported contexts and title overwrites with only temporary `activeTab` access.
- Modernized options UI with no runtime third-party dependencies and no background service worker.
- Firefox Android distribution metadata and explicit no-data-collection declaration.

## Validation

- Dependency-free unit and manifest tests.
- Mozilla `web-ext` lint with warnings treated as errors.
- Reproducible package-content validation.
- Real Chromium MV3 E2E including SPA navigation, dynamic titles, settings changes, input attributes, diagnostics, and a 40-tab release smoke test.
- Temporary installation and real E2E of the exact built package in current Firefox.
- Live regression smoke for GitHub Issues, X.com, and delayed Chase title rewrites.
- Controlled stress runs passed 250 and 500 simultaneous loaded Chromium tabs. Higher 750/1000-tab runs hit browser/test-harness timing limits without an extension crash or OOM; a ~2700-tab scenario is therefore not used as a release gate.

## Platform notes

- A third-party Android System WebView does not load Firefox/Chrome WebExtensions and is outside the extension's control.
- Waterfox 6.6.17 accepts the temporary add-on in CI, but its WebDriver temporary-install path does not inject even a minimal MV3 content script. Direct Waterfox desktop testing remains a post-release compatibility check rather than a release gate.
- Physical Firefox/Waterfox Android testing is also tracked as post-release compatibility validation.
